Data jobs

Two ways to fill your collection with data, and you can mix them freely. Every job runs in the background and takes a database backup first. Cancelling is always safe — everything already fetched is saved — but a job can't be resumed: to cover the rest, start it again and it skips what's already done.

Which should I use? The public APIs are free, fast and unblockable — use them for card names, art, types and rough prices. The Cardmarket scraper is slow and can be blocked, but it is the only source of real per-printing prices — what your Starlight Rare is actually worth, as opposed to what the card is worth on average. A normal setup runs the APIs often and the scraper occasionally.

Cardmarket sells cards but never says what they are. This downloads the game's whole card list from YGOPRODeck (Yu-Gi-Oh!) or digimoncard.io (Digimon) — name, type, attribute, level, ATK, archetype, banlist status, card text and artwork — into a reference library. It doesn't touch your quantities or prices. One request, about 15 seconds.

Run this first, and again every month or two for new sets.

Works out which library card each Cardmarket product actually is — that Dark-Magician-V1-Secret-Rare page in Soul Fusion is passcode 46986414. Nothing connects the two on its own: Cardmarket uses names with rarity tacked on, the library uses ID numbers.

Once matched, your cards get their picture, type, attribute, level and banlist badge, and the filters on the Cards page start working — nothing shows art until this has run. Seconds to a minute.

Worth ticking after importing a fresh catalog. Either way it never overwrites a match you made by hand in the admin.

Uses the catalog's Cardmarket price so cards the scraper has never priced still have a value. Cardmarket often lists no price for bulk commons — this fills those in.

These are per-card prices, not per-printing: a Starlight Rare and a Common of the same card get the same number. Fine for putting a value on bulk; not what you'd quote a buyer. Priced this way, cards are tagged “catalog estimate” everywhere they appear.

Cardmarket scraper slow · opens a browser

Cardmarket sits behind Cloudflare. A job opens a Chrome window — leave it visible. If it shows “Verify you are human”, click it and the job carries on by itself (it waits up to {{ config.challenge_timeout }}s). The browser profile is remembered, so this is usually a once-per-machine chore. If a run is blocked outright, wait 15–60 minutes rather than retrying — nothing is ever recorded from a blocked page.

Browser settings — Chrome path and pacing (scraper only)
{% csrf_token %}

Cloudflare wait: the check normally clears by itself in 5–15 s, so don't set this low — under 30 s you abandon runs that were about to succeed. 180 s leaves room for you to walk over and click a checkbox; you'll get a notification and a beep when one actually appears.

Patience: when a check still hasn't cleared after that wait, the job pauses (1, 5, 15, then 30 minutes), starts a fresh browser and puts the card back in the queue — so an unattended run survives the odd stubborn check instead of dying on it. Set 0 to stop at the first one. An outright “you have been blocked” always stops immediately; waiting can't help there.

Pacing: how long to wait between Cardmarket page loads — it applies to “discover cards” and “refresh prices”, not to the API jobs, which don't touch Cardmarket at all. Slower is safer: bursts are what get an IP blocked. For a long sweep 10–20 s costs hours, but a block costs a day.
